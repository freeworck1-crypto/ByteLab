# ByteLab persistent APK signing setup

This patch changes GitHub Actions to build a signed **release** APK using one persistent private signing key.
It also increases Android `versionCode` on every workflow run.

## One-time setup

1. Generate one keystore on your own computer or Android terminal. Keep it private and back it up safely:

   ```bash
   keytool -genkeypair -v -keystore bytelab-release.jks -storetype JKS -alias bytelab -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Convert it to one line of Base64:

   ```bash
   base64 -w 0 bytelab-release.jks
   ```

   Copy the complete output. Do not upload the `.jks` file to GitHub or commit it to the repository.

3. In GitHub, open **Repository → Settings → Secrets and variables → Actions → New repository secret**.
   Add these four secrets:

   - `BYTELAB_KEYSTORE_BASE64` = the complete Base64 output from step 2
   - `BYTELAB_STORE_PASSWORD` = the keystore password
   - `BYTELAB_KEY_ALIAS` = `bytelab` (or the alias you selected)
   - `BYTELAB_KEY_PASSWORD` = the key password

4. Push the two replacement files from this ZIP to the `main` branch. The workflow will produce `ByteLab-release-apks`.
   Install the `universal` APK from that artifact. Do not use `app-debug.apk` for future updates.

## Important first-install transition

Your previous workflow created a **new debug signing key on every run**. Android updates require the same signing certificate. If the private key that signed the currently installed APK was generated by an earlier GitHub run and was not saved, it cannot be reconstructed from the APK. Therefore, the first installation of this persistent release-signed build may require uninstalling the old ByteLab once.

After installing this new release APK, keep the keystore and all four GitHub secrets unchanged. Future builds from this workflow will update over the installed app without uninstalling, as long as the package ID remains `com.niaznix.bytelab`.

The app's current `applicationId` is preserved. Do not change it.
